```
사용자: 전원 버튼 1초 누름
폰: OS 전원 메뉴가 잠시 뜸 → 페이지 hidden
사용자: 캔슬해서 돌아옴 → 페이지 visible (1~2초 경과)
앱: visibilitychange 감지 → 가짜 종료 메뉴 표시
검사관: "Power off" 탭
앱: 검은 화면 + 음소거 + 자동 침묵 녹음 시작 (1분~60분)
검사관: 폰이 꺼졌다고 판단 → 다른 것 검사
사용자: 검은 화면 하단 중앙 (보이지 않는 영역) 탭
앱: 숫자 키패드 등장
사용자: 0000 입력 + OK
앱: 즉시 정상 화면 복구 + 녹음 파일 자동 저장
사용자: 검사관 모르게 증거 확보 완료
```

### OTF 심사관 답변

심사관이 "검사관이 폰을 끄라고 하면?" 질문 시 답변:

> **"In V4.0, the user pre-arms 'Power-Off Trick' from settings. When an inspector orders the phone off, the user presses the device's physical power button. The page detects the brief hide-show cycle via `visibilitychange` and displays a pixel-perfect fake Android shutdown menu. The inspector taps 'Power off' — the screen goes black, audio is muted to zero, and silent recording starts automatically for the configured duration (1/5/15/30/60 min). Recovery is dual: a hidden top-right 3-tap, and a hidden bottom-center tap that opens a numeric keypad accepting the user's unlock code (default 0000, customizable). The user can recover even from a 60-minute lockout. There are no toasts or alerts during recovery — silent by design, since an inspector may be watching. The 'Emergency call' button on the fake menu actually dials the local emergency number."**

### 사용자 결정이 필요한 후속 사안

**첫째**, `visibilitychange` 우회 감지의 한계 — 알림 확인이나 앱 전환 시에도 가짜 메뉴가 뜰 수 있습니다. 만약 이 오탐이 문제가 된다면, 다음 옵션 추가 가능:
- (A) 추가 조건: 빠른 연속 hidden-visible 2회 (사용자가 의도적으로 전원 버튼 두 번 누름)
- (B) 시간 윈도우 조정 (현재 200~3000ms)
- (C) 가짜 메뉴 표시 전 1초간 빈 화면 카운트다운 (취소 가능)

**둘째**, 검사관이 가짜 메뉴를 무시하고 실제 전원 버튼을 한 번 더 눌러 OS 전원 메뉴를 띄울 가능성. 이는 웹앱이 막을 수 없습니다 — 도움말에 "검사관이 의심하면 직접 폰을 손에서 놓지 말 것" 같은 운영 지침을 추가할 수 있습니다.

**셋째**, V4.0 도움말 패널(Help section)에 V3.9 작업 시 쌓인 Power-Off Trick 설명을 정식으로 추가할까요? 현재는 설정 다이얼로그로만 설명됩니다.

추가 수정 또는 OTF 제출용 문서 작업 요청 시 이어서 진행하겠습니다.
